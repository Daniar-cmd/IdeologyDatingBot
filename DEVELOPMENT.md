# Разработка: тестовый и боевой контуры

Проект можно запускать в двух контурах. Переключатель — переменная `BOT_ENV`.

| | Боевой (prod) | Тестовый (test) |
|---|---|---|
| Включение | `BOT_ENV` не задан (или любое значение, кроме `test`) | `BOT_ENV=test` |
| Токен бота | `BOT_TOKEN` (@ideologyDatingBot) | `TEST_BOT_TOKEN` (@IdeologyDating_TestBot) |
| Данные | `DATABASE_URL`, схема `public` | та же БД, схема `TEST_DB_SCHEMA` (по умолчанию `ideology_test`) |

В шапке запуска всегда печатается контур, например:

```
Режим: ТЕСТОВЫЙ — @IdeologyDating_TestBot (схема БД ideology_test)
Режим: БОЕВОЙ — @ideologyDatingBot (схема БД public)
```

## Переменные в .env

* `BOT_TOKEN` — боевой бот.
* `TEST_BOT_TOKEN` — тестовый бот.
* `DATABASE_URL` — рабочая БД (общая для обоих контуров).
* `TEST_DB_SCHEMA` — схема тестового контура (по умолчанию `ideology_test`). Необязательна.
* `TEST_DATABASE_URL` — если для теста выделена отдельная БД; тогда схема не нужна. Необязательна.

## Изоляция данных

Тестовый контур не видит и не портит боевые данные:

* по умолчанию все тестовые таблицы создаются и читаются в отдельной схеме БД
  (`ideology_test`) — боевые данные в схеме `public` не затрагиваются;
* схема создаётся автоматически при первом запуске (`CREATE SCHEMA IF NOT EXISTS`);
* использовать схему `public` в тестовом режиме запрещено — запуск завершится ошибкой;
* если у тебя есть отдельная тестовая база, задай `TEST_DATABASE_URL` — она полностью вынесена из боевой.

Также в тестовом режиме используется отдельный бот (`TEST_BOT_TOKEN`), поэтому
тестовый бот можно спокойно запускать локально параллельно с боевым на сервере.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Тестовый бот в watch-режиме (nodemon, `BOT_ENV=test`) |
| `npm run start:test` | Тестовый бот без watch |
| `npm start` | Боевой бот |
| `npm run admin:test` | Консоль модерации к тестовой схеме |
| `npm run admin` | Консоль модерации к боевой БД |

## Пайплайн

1. Меняешь код.
2. `npm run dev` — поднимается тестовый бот; проверяешь изменение в Telegram
   у `@IdeologyDating_TestBot`. Данные пишутся в схему `ideology_test`, живых
   пользователей тестовый бот не видит.
3. Прогоняешь стенды (см. раздел «Тестирование» в `AGENTS.md`).
4. Если изменение позитивное — коммит и push, затем на сервере `git pull` и
   перезапуск боевого процесса (`npm start`).

## Важно

* Не запускай боевой бот локально, пока он работает на сервере: Telegram
  вернёт `409 Conflict` (два поллинга одним токеном).
* Тестовый бот локально и боевой на сервере работают одновременно без конфликтов
  (разные токены).
* Сообщения пользователям из консоли модерации доставляет запущенный бот
  (см. раздел 5 в `AGENTS.md`), поэтому для проверки таких сценариев нужно
  использовать соответствующий контур и бота.
